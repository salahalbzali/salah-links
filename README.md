# Salah Links — منصة اختصار الروابط

واجهة عربية RTL مبنية باستخدام Next.js App Router وTypeScript وTailwind CSS وSupabase. تتضمن الصفحة التسويقية، التسجيل وتسجيل الدخول، لوحة إدارة الروابط، الروابط المخصصة، انتهاء الصلاحية، تفعيل/إيقاف/حذف الروابط، عداد النقرات، وإنشاء QR قابل للتنزيل.

> هذا مستودع تطبيق جاهز للنشر بعد ربط مشروع Supabase وضبط متغيرات البيئة. لا توجد مفاتيح سرية مضمنة. قبل الإطلاق التجاري، أكمل عناصر قائمة ما قبل الإطلاق أدناه.

## 1. المتطلبات
- Node.js 20.9 أو أحدث
- حساب Supabase
- Git وحساب استضافة مثل Vercel (اختياري محليًا)

## 2. الإعداد المحلي

```bash
npm install
cp .env.example .env.local
```

عدّل `.env.local` وضع `NEXT_PUBLIC_SUPABASE_URL` و`NEXT_PUBLIC_SUPABASE_ANON_KEY` من إعدادات مشروع Supabase. اترك `NEXT_PUBLIC_SITE_URL=http://localhost:3000` أثناء التطوير.

في Supabase افتح **SQL Editor** وشغّل كامل محتوى `supabase/schema.sql`.

ثم شغّل:

```bash
npm run dev
```

افتح `http://localhost:3000`.

## 3. إعداد المصادقة

من Supabase Dashboard > Authentication > URL Configuration:
- Site URL: عنوان موقعك الفعلي.
- أضف `http://localhost:3000/**` ضمن Redirect URLs للتطوير، وعنوان الإنتاج وفق إعدادات Supabase.
- إذا كانت ميزة تأكيد البريد الإلكتروني مفعّلة، يجب على المستخدم تأكيد البريد قبل تسجيل الدخول. اضبط SMTP مخصصًا للإنتاج بدل الاعتماد على رسائل الاختبار.

## 4. النشر على Vercel

1. ارفع المشروع إلى مستودع Git.
2. استورد المستودع في Vercel.
3. أضف متغيرات البيئة الثلاثة من `.env.example` في إعدادات المشروع.
4. غيّر `NEXT_PUBLIC_SITE_URL` إلى النطاق النهائي مثل `https://your-domain.com`.
5. أعد النشر، ثم أضف النطاق نفسه إلى إعدادات Site URL وRedirect URLs في Supabase.
6. اختبر التسجيل، إنشاء رابط، فتح الرابط القصير، انتهاء الصلاحية، إيقاف الرابط، QR، وتسجيل الخروج.

## 5. قاعدة البيانات والأمان

- سياسات RLS تجعل كل مستخدم يدير روابطه فقط.
- لا تستخدم مفتاح `service_role` في متغيرات `NEXT_PUBLIC_*` أو في المتصفح.
- دالة `resolve_short_link` مخصصة لحل الروابط وتحديث عداد النقرات دون إتاحة قراءة جدول الروابط مباشرة للزوار.
- الرموز المخصصة تقبل 4–32 حرفًا/رقمًا أو شرطة/شرطة سفلية.
- روابط الوجهة تقبل HTTP/HTTPS فقط.

## 6. ما يلزم قبل الإطلاق العام/التجاري

هذه النسخة توفر أساسًا عمليًا، لكنها لا تدّعي وجود تكاملات غير مفعّلة. قبل فتح التسجيل للعامة:

- إضافة سياسة خصوصية وشروط استخدام وصفحة إبلاغ عن إساءة الاستخدام.
- إضافة CAPTCHA وحدود معدل (rate limiting) لإنشاء الروابط وتسجيل الدخول، ووسيلة حماية من الروابط الخبيثة والتصيد.
- إعداد SMTP موثوق لتأكيد البريد واستعادة كلمة المرور، وإضافة تدفق استعادة كلمة المرور.
- إذا أردت سجل نقرات تفصيليًا حسب الدولة/الجهاز/المصدر، أضف خدمة خلفية موثوقة أو Edge Function؛ لا تثق في قيم التحليلات التي يرسلها العميل. لا تخزّن عناوين IP إلا لسبب مشروع وبسياسة واضحة.
- إذا أضفت اشتراكات مدفوعة، اربط مزود دفع يدعم بلدك وطبّق التحقق من webhooks على الخادم. لا تعتبر زرًا أو واجهة اشتراك بديلًا عن نظام فوترة حقيقي.
- أضف مراقبة أخطاء ونسخًا احتياطية وخطة استجابة لإساءة الاستخدام.

## 7. أوامر

```bash
npm run dev     # تطوير محلي
npm run build   # فحص بناء الإنتاج
npm start       # تشغيل بناء الإنتاج
```
